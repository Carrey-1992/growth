AI 模块 1 · Agent 循环、规则与上下文

1 · Agent 循环

重点：模型决策、工具执行、环境反馈、停止条件。

编码代理不是把整份需求一次生成完。它在一轮循环里工作：模型决定下一步，工具去读文件、改代码或跑命令，环境把真实结果送回来，直到做完或碰到停止条件。

是什么

Anthropic 把代理式系统分成两类。工作流是人和代码事先排好 LLM 与工具的路径。代理是模型自己决定流程和用哪个工具。文中的说法是：代理通常就是在循环里、根据环境反馈使用工具的 LLM。环境反馈包括工具返回值和代码执行结果，文中称为 ground truth。循环要有停止条件，例如最大迭代次数，或需要人来决定。

为什么这样设计

先用简单路径，只有收益明确时才把自主权加大。代理用更长的时间和更多 token 换“能自己往下做”。编码适合这种循环，是因为测试、编译和运行能给出可核对的结果，问题也相对有结构。工具要设计得不容易用错：文中的例子是模型在切换目录后用相对路径出错，后来工具只接受绝对路径。

什么时候会出问题

  • 没有环境反馈，模型只根据自己上一轮的话继续编，错误会叠加上去。
  • 没有停止条件，循环会一直烧上下文和费用。
  • 工具描述含糊，模型会调错工具或不调用。
  • 权限过大时，错误的一次工具调用会直接改到不该改的地方。

怎么验证过

留空。做完下面的 40 分钟任务后，用自己的话写四句：谁决策、谁执行、反馈从哪来、何时停。本页不代填。

必读与选读

必读 Building effective agents。读开头对 workflow 和 agent 的区分，以及把 agent 写成“在循环中根据环境反馈使用工具”的那一节，包含停止条件。不要第一遍通读后半的全部模式。

选读 同一页里讲工具接口（文中称 ACI）的例子：绝对路径。读完能说出“让工具难以用错”。

40–50 分钟

  2. 在纸上画一个你见过的编码任务：读需求 → 搜代码 → 改文件 → 跑测试 → 看失败 → 再改。标出哪一步是模型决策，哪一步是工具，哪一步是环境反馈。
  3. 写下你会放的一个停止条件。

验收：合上页面，能说出决策、执行、反馈、停止这四件事，并举出一个没有反馈时会怎样。做不到就回到必读那两处，不要先做 Java 项目。

2 · 原文对照，不是第二套原理

重点：用原文核对第 1 张的四句话。工作流可以先够用。

这张卡不重复讲循环。它只负责把第 1 张的中文和原文对上，并看作者什么时候建议不要上代理。

是什么

同一篇文章还列出几种固定路径：提示串起来、路由、并行、编排者分派、生成后再评估。它们是工作流。代理是模型在循环里自己选工具。两种都在这篇文章里，不要混成“用了 LLM 就是代理”。

为什么这样设计

作者建议从最简单的方案开始，只在复杂方案明显更好时才增加自主性。代理的代价是延迟、费用和错误叠加。

什么时候会出问题

任务步骤固定、用测试就能判定对错时，先写成工作流往往更稳。一开始就让模型自己规划，容易在错误假设上继续跑。框架若把提示和工具结果藏起来，会让你无法核对模型实际看到了什么。

怎么验证过

留空。记下你在原文里找到的一句原话，以及它对应四句话里的哪一句。

必读位置

Building effective agents。必读：workflow 与 agent 的定义；agent 循环与停止条件。选读：文中几种 workflow 模式的名字，以及 ACI 的绝对路径例子。本页不把原文贴进来。

30–40 分钟
  1. 打开上文，只找三处：工作流的定义、代理的定义、一个停止条件。
  2. 各抄一句短的原文（自己的笔记，不必贴回本页），旁边写它对应“决策 / 执行 / 反馈 / 停止”中的哪一个。
  3. 用一句话回答：什么情况下你不会让它自主循环。

验收：能指出工作流和代理的差别，且不把第 1 张的四句话再说成另一门课。

3 · 规则文件

重点：规则是每次带上的上下文，不是强制开关。句子要能检查。

新会话通常不记得上次的口头约定。规则文件把稳定的项目事实放进上下文。它不能代替权限控制和测试。

是什么

Claude Code 用 CLAUDE.md 一类记忆文件，在会话开始时加载。Cursor 的项目规则、以及 AGENTS.md，也是写给编码代理的持久说明。内容适合放：构建命令、目录约定、禁止的写法和必须有的测试。不适合把一整本手册都塞进去。

为什么这样设计

模型不会自动知道你的包结构、构建命令和评审标准。把这些写成短而可核对的句子，比在每次聊天里重贴一段更稳。官方对 Claude Code 的说明是：这类文件是上下文，不是强制配置。

什么时候会出问题

  • 规则含糊或互相矛盾，模型会任选一条。
  • 文件过长。Claude Code 文档建议单个 CLAUDE.md 尽量控制在 200 行以内，越长越占上下文，也越不容易被遵守。
  • 需要硬性拦住某个操作时，只写在规则里不够，应使用权限或 hook。

怎么验证过

留空。做完练习后写：哪一条被遵守，哪一条没有，你怎么改写的。

阅读

必读 Claude Code：CLAUDE.md 与记忆。读它如何被加载、它是上下文而不是强制配置、以及关于篇幅的建议。若页面路径有跳转，以打开后的 Memory / CLAUDE.md 章节为准。

选读 Cursor 文档里项目规则（Project Rules）的说明：规则何时进入上下文。首页会指向当前规则文档，本页不猜一个可能过期的深层路径。

记忆文档

读加载方式和“上下文，不是强制配置”。勾选表示这页你读过，不表示实验已在本机做完。

Cursor 文档

选读项目规则。与 CLAUDE.md 对照：两者都是上下文，都不是编译器。

40–60 分钟
  1. 读必读里关于加载和篇幅的段落。
  2. 写 5 条能打勾的规则，例如“测试命令是 mvn -q test”“新接口要有测试”“不要用字段注入”。每条都要能在 diff 里看出有没有做到。
  3. 把一条故意写成“代码要优雅”。对比它为什么没法验收。

验收：5 条里每一条都能回答“怎样算违反了”。说不清的改写，直到能回答。

4 · 上下文与成本

重点：循环的每一步都把历史和工具结果放进窗口。又长又贵，早期信息会挤掉。

是什么

上下文窗口是这一次调用里模型能看见的文本上限。代理每转一圈，都会把对话、读过的文件和工具输出继续放进去。规则文件、已加载的 Skill 说明也占这里。

为什么这样设计

模型看不到窗口外面的东西。要把项目约定带上，就得放进上下文；要让下一轮知道测试失败了什么，也得把失败输出放进来。这是循环能继续的原因，也是费用和遗忘的原因。

什么时候会出问题

  • 任务一长，开头的需求或规则被截掉，后面的修改和最初约定不一致。
  • 把整库日志或无关文件塞进去，既贵，也让真正的错误信息难找。
  • 具体窗口大小和价格随模型变化。这里不写数字。

怎么验证过

留空。若你用过带上下文用量显示的工具，只记你自己看到的现象。

必读 仍是 Building effective agents 里说明代理用延迟和成本换效果的段落，对照 记忆文档里关于文件变长会占用上下文的说明。

Claude Code 概览

概览。选读：它如何把工具用在本地工程里。用来建立地图即可，不必按安装教程重做环境。

30–40 分钟

  2. 列出三类不该整段塞进上下文的东西：无关大文件、重复规则、已经过时的报错。
  3. 写一句：规则文件变长时，第 3 张说的“遵守变差”和第 4 张说的“窗口被占用”是同一件事的两面。

验收：能解释为什么循环越长越容易丢掉开头的约定，且不引用任何未核对的价格数字。

5 · 回忆题

重点：先答再展开。答错的题回到对应卡片，不要只点开答案。

  1. 工作流和代理差在哪里？
    参考答案

    工作流的路径事先写好。代理由模型在循环里决定下一步和用哪个工具。

  2. 循环里的四件事是什么？
    参考答案

    模型决策，工具执行，环境把真实结果反馈回来，并且要有停止条件。

  3. 为什么每一步都要环境反馈？
    参考答案

    测试输出、编译错误、工具返回值才是这轮的依据。没有它，模型会沿着自己的错误假设继续。

  4. 规则写了却没被遵守，可能是什么原因？
    参考答案

    规则只是上下文。句子含糊、互相矛盾或文件过长都会降低遵守度。必须拦住的操作要用权限或 hook，不能只靠一段说明。

  5. 上下文变长会怎样？
    参考答案

    费用和延迟上升，早期的需求或规则可能被挤出窗口，后面的修改和开头约定不一致。

验收：五题能脱开资料回答。答错的回到第 1–4 张，而不是把答案抄一遍就算完成。

最小练习 · 有无规则各做一次

有空再做，大约 60 分钟。不是日历上的某个周末作业。本站没有代跑过这个实验。

  1. 选一个你已经能跑通测试的小项目。没有就停在第 3 张的纸面规则，不要为了本练习新开一套环境。
  2. 先不要放规则文件，让编码代理完成一个小需求，例如给现有接口补一个查询并带测试。保存 diff。
  3. 加上你在第 3 张写的 5 条规则，新开一个会话再做同一个需求。保存第二份 diff。
  4. 对照：包结构、注入方式、有没有测试、有没有自己跑测试。哪条没被遵守，就改写成更能检查的句子再试一次。

验收：笔记里有两份 diff 的差异，以及一条改写前后的规则。没做就不要把上面的“怎么验证过”填成已经发生。
